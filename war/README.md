# v0.2 重构说明（AI 与规则内核修复）

## 运行与测试

```bash
open index.html          # 浏览器直接打开即可玩
node tests/kernel.test.mjs   # 27 项规则/AI 回归测试
```

零依赖，纯前端。`config.js / item.js / field.js / ai.js` 完全不碰 DOM，
因此同一套内核逻辑可原样移植到 iOS(Swift) 或 Node 服务端。

## 本次修掉的缺陷

### P0 规则被破坏（导致"AI 强弱"的结论全都不可信）

| 缺陷 | 位置 | 后果 |
|---|---|---|
| `Battlefield.moveUnit()` 更新 grid 但不扣行动点；`Unit.move()` 扣点但不更新 grid | field.js / item.js | 移动完全免费，玩家与 AI 都能一回合无限走 |
| AI 主循环 `while (remainingActionPoints > 0)` 靠 `maxActions = 10` 截断 | ai.js | AI 每回合白走最多 9 格，`moveRange` 形同虚设 |
| AI 走位同时取 dx 与 dy，落点是曼哈顿距离 2 的斜角，而 `moveUnit` 不校验距离 | ai.js | AI 能斜走、一次跨 2 格，玩家不能 —— 规则不对称 |
| `calculateSurroundingValue` 中 `ally !== this.unit`，`AI` 上并无 `unit` 属性 | ai.js | 条件恒真，把自己算进包围数，评分虚高 |

修法：坐标与占位网格的**唯一写入者**是 `Battlefield.moveAlongPath()`，它逐步校验
4 邻接、空格、地形消耗并同步扣机动点；失败时回滚，不留部分副作用。
`Unit` 退化为纯状态对象，不再自己改坐标。

### P1 打分函数

- **medium 难度实际退化成"固定优先打弓兵"**：`threat*0.6`（量级 50~62）压制了
  `(1-health)*0.3`（最大 0.3）与 `surround*0.1`（最大 0.4）。现在所有分项先归一化
  到 `[0,1]` 再乘权重，权重量纲统一，可逐项调。
- **三套难度 = 三份不同算法** → 难度不可连续调节、结果不可复现。现在难度只是三个
  正交旋钮（见下）。
- **缺少 `(位置, 动作)` 联合枚举**：旧的"先试着打 → 再试着走"贪心顺序无法表达
  "走到位再开火""为包围放弃本轮击杀"。现在一次摊开全部候选交给同一个评分器。
- **没有待命候选**：AI 永远被迫行动。现在 `wait` 是基线候选，"不动比乱动好"才可表达。

### P2 缺失骨架

新增：地形（机动消耗 + 防御加成 + 不可通行）、视线遮挡（射程 2 直线射击）、
近战反击、威胁影响图（按敌方**完整机动力**外扩射程，即"下回合威胁"而非"当前射程圈"）、
战略层（物质差 → 进攻/防守/冲锋/包抄/撤退 + 集火锁定）、浅层前瞻 rollout、
确定性种子随机、可回滚快照、AI 决策日志与可视化 overlay。

## 难度 = 三个正交旋钮（不再靠给敌方加数值）

| 旋钮 | 含义 | easy | normal | hard | nightmare |
|---|---|---|---|---|---|
| `vision` | 能看多远（信息） | 5 | 9 | ∞ | ∞ |
| `temperature` | softmax 随机度（犯蠢率） | 0.90 | 0.35 | 0.10 | 0.02 |
| `lookahead` | 推演步数（前瞻） | 0 | 0 | 1 | 2 |

实测（`node tests/kernel.test.mjs`）：nightmare 对 easy 8 胜 0 负；
hard(前瞻1) 对 normal(无前瞻) 3 胜 1 负；20v20 nightmare 每阵营回合约 12ms。

## 与原始需求的偏离（有意为之）

1. **行动力**：需求写"移动算一步，攻击算一步"的统一 AP 池。统一池在射程 2 兵种上
   会产生"走过一格就不能射击"的伪约束，且是本次 P0 bug 的温床。现拆为
   `moveBudget`（按地形累扣）+ `attackBudget`（攻击次数）两个独立预算 —— 即
   火焰纹章式模型，仍满足"移动与攻击都要花东西"的原意。
2. **棋盘尺寸**：需求写 16×16，旧代码实为 20×20。现收敛到 `WarConfig.board`
   一处定义（当前 20×20），改尺寸只动一个数字。
3. 新增反击与地形，是为了让 AI 的"期望净伤害"有意义；否则最优解永远是贴脸换血。

## 文件结构

```
config.js   地形/兵种/难度旋钮/评分权重/种子随机 —— 数值唯一定义处
item.js     Unit：纯状态 + 伤害与配额的纯函数
field.js    Battlefield：地形与占位、移动与攻击结算、可达域、威胁影响图、快照
ai.js       Strategist → Enumerator → Scorer → Lookahead → WarAI
game.js     状态机 + DOM 渲染 + AI 回合事件重放动画 + 调试 overlay
tests/      零依赖回归测试（node 直接跑）
```
